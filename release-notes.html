Studios, Progressions & Cadence Map

Pattern Studio

Pattern Studio contains 500 generated patterns from 42 forms across 12 keys. Load/search the library, arrange interval/chord/scale blocks with root and duration, set key/tempo, play/stop, save named patterns and transfer status backups. MIDI exports include individual arrangements and an all-pattern ZIP with a compiled MIDI that preserves section keys.

Progression tools

Chord Progressions retains its builder, presets, transposition, favorites, playback and diagrams. Andalusian Cadence retains its focused progression variations, musical explanations and playback.

Cadence Map

Cadence Map combines a six-chord minor palette with triads from all seven major-scale modes. Select one or all 12 tonics, multiple lengths and chord-count shapes; browse progression ranks by page and play a chosen sequence. Featured four-chord recipes have 24 unique orderings per tonic. TXT exports expand selections up to the 25,000-progression limit; larger selections use a compact complete recipe/rank index. DM Mono, DM Sans, Instrument Serif and their licenses are local. Only the optional original-project link needs internet.

Theory Decks suite

The preserved nested app includes cards, games, references, themes/card styles, active pools, pitch-based audio, author/release pages and dedicated settings. Its DAW supports bars, sections, arrangements, step editing, key/scale/meter/tempo changes, swing, mix, melody/chord/bass/drum lanes, undo/redo, local songs, MIDI import and supported local exports. Its companion fretboard supports individually tuned strings, note/degree labels, range/capo, arpeggios, saved setups and image/document/MIDI exports. Main Pattern Studio and Theory Decks DAW are separate tools with separate saved records.

Saved Data, Backups & Privacy

Settings, favorites, progress, notes, saved patterns, songs, test marks and Admin visibility choices remain in this browser profile on this origin. Offline Architecture

  • offline-assets.js is the authoritative list of all shipped pages and assets. The root worker, nested Theory Decks worker, Admin/documentation inventory and ZIP exporters consume it. Counts below are generated from that list.
  • The root sw.js uses a versioned cache scoped to the installation path. Theory Decks imports the same manifest and keeps its own path-scoped cache; entering the nested app also registers the parent worker so links back to main pages can work offline after installation completes.
  • Installation downloads mandatory assets in bounded batches, retrying individual files up to three times. A missing required file fails the install and removes that partial new cache. Existing completed versions are not removed by a failed new install.
  • The root readiness marker is written only after every asset succeeds. Successful activation claims pages and removes stale versions belonging to that app scope. Imported manifest updates bypass the HTTP script cache when the shared registration requests updates.
  • Cached GET requests are served locally first. Query strings on known files do not prevent cache matches. Folder addresses resolve to their own cached index documents before trying the network. Missing uncached routes show an explicit offline response rather than silently opening Home.
  • Fonts, libraries, musical formulas, datasets, icons, audio resources and retained UI files are local. Audio is predominantly synthesized with Web Audio; exports do not require a server.
  • Testing-page reference checks use GET so they can be answered by the workers while offline. First-party runtime code does not rely on an AI service, remote font CDN, analytics or a cloud music API.
  • Initial hosted installation, updates and the optional original-project link require internet. Host-platform chrome is outside the app's offline package. A complete extracted package served on localhost needs no internet.

Install, Update & Package

  1. Hosted install: open the HTTPS app while connected, follow the persistent Admin link on Home, and wait until its status says ready to work offline. Admin reports installation readiness in either view.
  2. Check before travel: after readiness, disconnect the network, reopen a tool from Admin, reload it and try playback/export. Keep the same browser profile/origin and do not clear site data.
  3. Installable app: use the browser's Install app / Add to Home Screen option. On iPhone/iPad, use Safari's Share menu and open the installed app while online once to finish caching. Installed launches use the saved Default/Custom Home view and retain the Admin link.
  4. Offline ZIP: use Admin or these Release Notes after a complete cache install. Root packaging verifies the readiness marker and every manifest entry, retains folder structure and creates its ZIP locally. The Theory Decks package includes the same complete parent app without unsafe parent-directory ZIP entries.
  5. Extracted package: extract the entire folder without renaming dependencies. With Python already installed, run python -m http.server 8000 inside that folder, then open http://localhost:8000/index.html. This local server does not need internet. Follow the included OFFLINE-START-HERE.txt.
  6. Do not assume file://: direct file opening is not fully supported because ES modules, local fetch, storage and download permissions vary. iOS Files previews are not an app installation mechanism.
  7. Updates: reconnect and reopen the hosted app to let a new version fully install, then reopen pages. Do not interrupt the download or delete working caches as an update step. The ZIP is a snapshot; replace extracted app files deliberately while preserving separate data backups.

FAQ

Where did Home go?

Use Admin > App view > Default to restore the pre-consolidation dashboard. Custom setup builds Home from saved Show/Hide choices. No tool was deleted, and both original Home URLs remain valid.

Does Hide disable a page or asset?

No. In Custom setup, page switches affect Home and the shared header's local navigation eligibility. Default ignores them without erasing them. Asset switches fold inventory details. Files, direct URLs, offline caches, documentation and ZIPs remain intact.

Is Admin private?

No. It is an offline catalog/staging interface, not a signed-in admin area or authorization boundary.

Will everything work without internet?

All first-party runtime dependencies are local and included in the full install. Complete hosted caching first, or use the complete ZIP on localhost. Browser capabilities, storage availability, audio permission and memory limits still apply; this is not an unconditional every-device guarantee.

Will the ZIP carry my music and notes?

The root package contains the application, not browser-local records. Export those separately. Theory Decks adds a settings/song JSON backup alongside the application, which must be imported deliberately.

Are all pages listed?

Yes. The page registry is validated against all HTML entry points, and the asset inventory is generated from the offline manifest. Home aliases and nested pages are included separately.

Troubleshooting & Recovery

  • Not ready offline: stay connected and let installation finish. Verify Admin or Release Notes status; a network icon alone is not proof of cache completeness. Low disk space, denied storage and private browsing can block installation.
  • Hidden navigation: open Admin from Home and Show the desired page. The direct link in Admin always works. Asset-detail Hide is not a dependency switch.
  • Wrong/stale UI: reconnect for the current manifest/worker update and reopen the page after installation. A hidden page is still cached; hiding it does not force a refresh.
  • Missing offline route: reconnect and complete the full current install, or verify the extracted folder has every file. Do not move nested folders or rename paths containing spaces.
  • ZIP or module failure: use localhost rather than file://. An archive opened in a file preview is not the running app. Check browser download permissions and the included start guide.
  • No sound: tap Play/Hear, check media volume and output routing, resume after interruptions and check silent-mode behavior on your device.
  • Lost records: check profile/origin/device and restore a matching backup. Do not reset or clear site data as a generic fix.
  • Huge export stalls: reduce the collection, use Stop when supported, and allow browser memory/time. Stop does not turn an unfinished collection into a complete one.

Known Limits

  • First hosted install and updates require a connection; the optional original-project link is online-only.
  • Cached storage can be denied, evicted or cleared. Local saved data is not cloud-synchronized.
  • Direct file:// execution is not fully supported; use localhost or an installed hosted app.
  • Admin is not access control, not a file editor/deletion tool and not a site-wide published visibility switch.
  • Main and Theory Decks tools have different feature sets, import/export formats and saved-state conventions. There is no universal recording, notation or MIDI-input layer.
  • Some catalog entries use formula-based names; spelling conventions and glyph support differ by tool and export format.
  • Large PDF/Word/ZIP jobs can exhaust memory, particularly on phones. Audio/download/background policies differ by browser and OS.
  • The UI overhaul has not yet been applied to preserved tools. Their legacy styles and documentation remain in the package; component history is not a claim that every historical assertion was re-verified.
